# NT51928B normal-mode gate

The unchanged no-overlay interface is verified:

```text
NT51928BBASED_NORMAL_MODE <CRC8|CRC32> <output-bin> <firmware-bin> \
  <block-bin> <source-hex> <destination-hex> <length-dec> [...]
```

## 2026-11-13 FwConfig requirement

On 2026-11-13 the owner changed the C function `NT51928B_MergeBinsThenInsertFwConfig`:

- The FwConfig copy goes to `0x33100` instead of `0x3E000`.
- It copies 4092 bytes instead of 1920.
- The NVT end flag `00 4E 56 54` follows at `0x340FC..0x340FF`.
- The tool prints `EndFlag Address = 0x340FC`.

NT51928B therefore no longer matches the legacy Combiner 1.13 EXE. Its differential tests need a second private oracle: a reference EXE built from the updated C source (SHA-256 `d4536db0183920d0214fd2654f7f9d60d412995f03aed7cee1205d6358d3c239`). Set `NVT_COMBINER_NT51928B_ORACLE` to its absolute path. Without it, the NT51928B differential tests skip. The console banner still says `Combiner version:1.13.0.0`.

## Differential tests

`tests/module/test_nt51928b.py` compares the reference EXE against Python for process exit code, stdout and every output byte. It covers:

- the 4092-byte FwConfig copy to `0x33100`, the end flag, ILM/DLM data CRCs and the 0x30-byte `0xD100` header CRC;
- both CRC methods;
- firmware of `0x3E780` bytes and of the minimum valid size `0x34100` bytes.

A further test reads the reference EXE output alone. It checks the copied bytes at `0x33100..0x340FB`, the end flag and both console lines.

| CRC method | Reference output SHA-256 (`0x3E780` fixture) |
| --- | --- |

`tests/module/test_nt51928b_overlay.py` adds one ordinary `_ovly_table =` descriptor for both CRC methods:

## Firmware smaller than the FwConfig area

The C buffer is `max(firmware size, highest block end)`. The new code writes up to `0x340FF`. With a smaller buffer, the C version writes past its heap buffer, which is undefined behavior. The C version also reads past the buffer when the config source address plus 4092 exceeds it.

Python rejects these inputs before any output is written, as `docs/architecture.md` requires. It does not enlarge the buffer. `tests/module/test_write_safety_failures.py` locks three cases. These tests need no oracle:

| Input | Python result |
| --- | --- |
| firmware `0x34000` bytes | `NT51928B FW config: destination range out of bounds; start=209152, length=4092, end=213244, buffer_size=212992, available=3840` |
| firmware `0x340FC` bytes | `NT51928B FW config end flag: destination range out of bounds; start=213244, length=4, end=213248, buffer_size=213244, available=0` |
| config source `0x3E000` in `0x3E780` bytes | `NT51928B FW config: source range out of bounds; start=253952, length=4092, end=258044, buffer_size=255872, available=1920` |

Excluded: HostDL/Process `OverlayDLMaddr` mutation and invalid pointer/source-range calls that depend on undefined C memory behavior.
