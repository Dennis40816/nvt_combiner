# NT51931 normal-mode gate

The unchanged interface is covered for a no-overlay map:

```text
NT51931BASED_NORMAL_MODE <CRC8|CRC32> <output-bin> <firmware-bin> \
  <block-bin> <source-hex> <destination-hex> <length-dec> [...]
```

`tests/module/test_nt51931.py` runs the pinned 1.13 EXE and Python with
identical arguments, comparing exit code, stdout, and the complete output
binary.  Its fixture includes two DLM-diff entries, the three `0x30..0x50`
firmware-header sections and the optional `0xF0` firmware-header CRC.

| CRC method | Reference output SHA-256 |
| --- | --- |
| CRC8 | `0d74019d650b1553258e41f3a427f3ad9265c7e6edaeb6e115eb0d0a902e578a` |
| CRC32 | `a92d3efc6f8f224ba6fd7f04cb239f87c46b778e8024d9460613afef164c4765` |

`tests/module/test_nt51931_overlay.py` further verifies the ordinary
`_ovly_table =` count/descriptor path for both CRC methods:

| CRC method | Reference overlay output SHA-256 |
| --- | --- |
| CRC8 | `029f9736688287b1bb33cacfa5f5f003ae782fe756d69c43efcc9a67a466ff7b` |
| CRC32 | `3c24c12c78d8ac91d7bdfa05e9315a96e496eb67f0bb084e135865e915aae9df` |

Excluded: HostDL/Process `OverlayDLMaddr` mutation and undefined C behavior
for malformed pointers, source ranges or allocator gaps.
